# Audit, August 2026 — what to do next, and what not to

Six independent audits ran against `acronymkit` 0.3.0 immediately after publication, followed by two
adversarial passes whose only job was to break them. This page is the surviving result. It answers
four questions in order: how to make the library significantly better, how to get data to test it
with, which unknowns are worth money, and how to let people extend it.

**Read section 0 first.** The adversarial passes killed four headline findings and five proposals.
Some of the killed items are more useful than the survivors, because they are the shapes this project
keeps falling into. That section is the shortest path to not re-litigating a question that has
already been settled twice.

**How numbers are handled here.** Figures that live in `bench/results.json` are named by run id.
Figures measured during the audit but never written through a bench runner are marked `un-gated`, and
the command or check that produced them is given. Nothing on this page may be quoted into README.md,
`docs/EVALUATION.md` or a docstring until it has gone through a runner's `--save` — that is operating
rule 1, and an audit page is not an exemption from it.

## 0. What did not survive

### The governed subsystem was scored on a corpus of invented names

Auditor 6 measured `expand_identifier` against Amazon's NameGuess and reported it as "9,218
human-annotated real column names". The adversarial pass queried the live Socrata metadata API for
the very tables NameGuess cites, and found the corpus is the other way round: the strings the library
was scored *on* are abbreviations the annotators invented, and the real portal names are the gold
answers.

```
un-gated -- adversarial re-check, 32 NameGuess tables, 291 columns, live Socrata metadata API
  NameGuess `gt_label`       matches a real portal column   289/291   99.0 %
  NameGuess `technical_name` matches a real portal column     8/291    2.7 %
NameGuess paper, S3.3.1, annotator instruction 3:
  "If in a well-curated form, provide only an 'abbreviated variant'"
S3.3.2 defines difficulty as edit distance from the gold label
```

The arithmetic auditor 6 published reproduces exactly. The task it measures does not occur in any
schema. The same check found the deeper fact, which is question 3's largest open item: real schemas
are mostly not abbreviated at all.

```
un-gated -- alphanumeric case-folded identity between input and gold
  NameGuess pairs identical                          185 / 9,218     2.0 %  (98.0 % abbreviated)
  real Socrata field/display pairs identical   143,749 / 164,652    87.3 %  (12.7 % abbreviated)
```

**The shape.** A benchmark's README says "real". Check what the annotator was *instructed* to
produce. This is PLOD's lesson — `bench/splits.toml`, `[corpora.plod]` — arriving through a different
door.

### The governed round trip is not broken

Auditor 1 reported that `to_physical_name(expand_identifier(x).phrase) == x` holds for `1.81 %` of
107,012 real identifiers, and called `audit_identifiers` reporting `round_trip_inconsistent = 0` a
reporting hazard. Both halves reproduce. Neither is a defect.

```
un-gated -- adversarial re-check, same 107,012-identifier corpus, empty catalog
  literal   f(g(x)) == x                       1.81 %   (0.00 % on socrata/sec_xbrl/fhir/openfda)
  f(g(x)) == normalize(x)                    100.00 %   -- and 100.00 % on all eight sources
```

`docs/GOVERNED_NAMING.md` states the generous form, says of it in advance that "Stated generously it
is false, and stated exactly it is useful", lists three preconditions an empty catalog over legacy
identifiers cannot meet, and tests the sharper form. `round_trip_inconsistent` counts what the
documentation says it counts, and it is right. What is missing is one sentence saying that on a
legacy schema the `corrected` bucket holds nearly everything — a documentation gap, not a bug, and it
is folded into recommendation 5.

### `41.53` is not a ceiling

Auditor 3's disambiguation diagnosis is otherwise the strongest work in the batch, and its central
framing is over-stated. It labels `verbatim_evidence_plus_chance` "the ceiling of the feature set"
and concludes the approach is exhausted rather than mistuned. The same run exceeds it four times,
once on the next printed line.

```
bench/results.json, disambiguation.sdu21.diagnosis.{ceilings,ablation}
  verbatim_evidence_plus_chance            41.53    labelled "the ceiling of the feature set"
  shipped_blend                            41.65
  overlap_only                             42.04
  perfect_tie_break                        42.38
  shipped_blend_inline_disabled            43.50
  best_reweighting_tuning_split            43.82    (dev-tuned)
```

The bound's premise — a silent feature set cannot beat chance — is contradicted by that run's own
finding that the character-bigram tier fires on `81.7 %` of comparisons and scores above the chance
floor where gold is absent. It is weak, not silent. The honest statement is smaller and still
decisive: re-weighting the three existing terms is worth about two points, which is exactly why the
frequency prior matters and the re-weighting does not. Auditor 3's recommendations survive; the word
"ceiling" does not.

### The frequency-count gap is not closed

Auditor 6 reported GLADIS as a permissively-licensed source of expansion counts, closing a gap D-020
left open across ten candidates. The licence was read from a GitHub badge.

```
un-gated -- verified live, 2026-08-23
  api.github.com/repos/tigerchen52/GLADIS   ->  license.spdx_id   CC0-1.0
  zenodo.org/api/records/7568937            ->  metadata.license  cc-by-4.0
  the repo README's own source table for the Acronym Dictionary lists:
    Pile (MIT license), Wikidata, UMLS
```

UMLS is distributed under a per-user Metathesaurus License Agreement and is not redistributable.
Three sources give three answers and one of them is dispositive against vendoring. Benchmark use is
defensible under the project's own redistribution-versus-use distinction; shipping is not, and D-020
stands.

### Five proposals that should not be built

| Proposal | Why not |
|---|---|
| Take D-012's "untried" per-candidate-evidence lever, with GLADIS or PMC | Now closed three times over — see the *do not* list at the end of question 1 |
| Mirror 80 GB of PMC to build a frequency prior | Measured sense coverage of the target inventory is `4.72 %`, and the table is four orders of magnitude over the wheel budget |
| Vendor `SecureFinAI-Lab/Regulations_abbreviation` as a governed catalogue | Covers `1.124 %` of real token occurrences, and the matches are homographs — `POP`, `CAR`, `CT`, `IT` — so it would make the refuse-to-guess subsystem guess |
| Auditor 1's bracket fix as specified (strip `[` `]` only when they wrap the whole identifier) | Verified to break the SQL case the rule exists for: `[db].[schema].[TXN_ID]` |
| Publish the strategy cascade as an accuracy lever | D-008 and D-010 each built and reverted an experiment on exactly this signal |

## 1. How to make this significantly better

Ranked by measured value against effort. Every item states how it could fail.

### 1. Make the disambiguator abstain, and let the caller supply a prior — days

The largest measured improvement anywhere in the audit, by an order of magnitude, and the only large
one that needs no corpus, no licence and no shipped data.

```
bench/results.json, disambiguation.sdu21.*
  acronymkit.accuracy                                                    41.65   dev
  most_frequent.accuracy                                                 72.84
  diagnosis.frequency_prior.accuracy_prior_only                          72.95   caller counts alone
  diagnosis.frequency_prior.accuracy_interpolation_out_of_fold           76.67   lambda 0.60, both folds
  diagnosis.frequency_prior.accuracy_oracle_union                        84.28   bound on any combination
  diagnosis.frequency_prior.instances_context_right_prior_wrong_pct      11.33
```

Two changes, and the first is free. **Abstention** ships today: the engine already computes a
top1–top2 margin and discards it.

```
bench/results.json, disambiguation.sdu21.diagnosis.abstention
  margin gate      coverage %      accuracy when answered
  0.00               100.00                41.65
  0.02                50.88                52.30
  0.10                22.67                70.35
  0.20                11.00                76.21
```

**A weighted dictionary** is the second: let `ExpansionDictionary` carry an optional count or weight
per expansion and blend it with the context score. Ship no counts. This is the same
caller-supplies-the-catalog contract `acronymkit.governed` already runs, in the same codebase, and it
converts D-020's unsolved problem from a blocker into a documented integration point — the library
stops needing to own data it cannot obtain. The class docstring already calls insertion order "weak
evidence" while the scorer ignores it entirely, so the intent is half-present.

**How it fails.** `lambda = 0.60` was fitted against one prior, drawn from the same corpus and domain
as the evaluation; a caller's prior will be sparser and differently smoothed, and a hard-coded
default blend could underperform their prior alone. The margin thresholds come from a split
`bench/splits.toml` declares `role = "tuning"`, and a margin is not a probability — on a two-candidate
set it is mechanically larger than on a fifteen-candidate one, so one global threshold abstains
unevenly and may need to be per-arity. Abstention is a breaking change for anyone treating
`primary_expansion` as always populated. And the whole thing may be built for nobody: question 3,
gap 2.

### 2. Publish the governed subsystem's first accuracy figures — days

The governed subsystem is `9,370` of `25,210` source lines and `42` of `87` public symbols, and has
never carried an accuracy number. The docs justify that with "exact by construction, which is a
tautology rather than a measurement". The audit produced a real figure, and it is good news the
project currently cannot state.

```
un-gated -- gold is the publisher-authored label, admitted only when its alphanumerics case-fold
equal to the identifier's AND it contains whitespace, so only cut placement can differ
  SEC XBRL   2,999 aligned pairs   exact 98.03 %   boundary F1 99.81 %
  Socrata   17,210 aligned pairs   exact 93.37 %   boundary F1 98.34 %
  subset where the identifier carries boundary marks     exact 96.23 %
  subset where it carries none                           exact 20.71 %, boundary recall 3.11 %
  120-pair hand pass by the auditor                      110/120 = 91.7 %
```

Publish it decomposed, never pooled. The flatcase row is the honest cost of refusing to guess and
belongs in the same table as the headline. Route it through a bench runner with `--save` and record
both gold derivations in `bench/splits.toml` as uncontaminated — neither corpus was ever used to tune
anything.

**Do not publish the NameGuess figure as governed accuracy.** If NameGuess is used at all it must be
labelled as what it measures: expansion of deliberately abbreviated names, which is a different and
harder task than the one real schemas present.

**How it fails.** The gold is how a publisher captioned a column, not how a data-governance function
would rule; the hand pass says the automated number is optimistic by about a point and a half, and a
second annotator could move that further. It covers two of the eight identifier shapes — no
UPPER_SNAKE and no dotted source has a label to align against — so it does not transfer to FEC- or
World-Bank-shaped input.

### 3. Ship the two short-form span fixes — separately, not together — hours

Both are written and measured in `bench/run_shortform.py`. Porting them into
`src/acronymkit/extractor.py` is a few lines each.

```
bench/results.json, shortform.med1250_all.high_precision.*
  variant           P %      R %      F1 %
  baseline        92.07    76.99    83.85
  balanced_trim   92.46    77.31    84.21
  two_word        92.79    77.97    84.74
  both            93.27    78.38    85.18
and independently on both frozen halves:
  shortform.med1250_dev.high_precision.both     85.04
  shortform.med1250_test.high_precision.both    85.32
```

`balanced_trim` stops `_trim_span` leaving an opening bracket unmatched, so `FEV(1)` no longer
becomes the short form `FEV(1`. `two_word` lets `_pair_for_region` prefer the whole two-word
bracketed text when it aligns — which `is_valid_short_form` already admits and `_short_form_in` never
offers.

**The adversarial pass established these are not one change.** On PLOD, `balanced_trim` is exactly
neutral on all four short-form metrics on both splits; `two_word` costs pooled short-form precision.
On SDU@AAAI-22 legal, `two_word` *raises* short-form precision and recall. So `balanced_trim` is free
everywhere and ships alone; `two_word` is a trade whose sign depends on the corpus, and it must be
recorded with both deltas beside it.

**How it fails.** MED1250 is a tuning split, and PLOD is structurally blind to both phenomena — zero
of its `2,869` gold short-form spans are multi-token and `1.50 %` carry a bracket — so there is no
clean independent corroboration on biomedical text. `two_word` overrides the first-word rule, and a
parenthetical gloss like `(WHO 2021)` could align spuriously in general prose.

### 4. Reject a long form that begins with a function word — hours

The cheapest correctness fix in the audit, re-measured for this page.

```
un-gated -- PYTHONPATH=src python, high_precision settings, bench.corpora.read_med1250()
  predictions                                                     1,021
  predictions whose long form starts with a function word              3   (0.29 %)
    of hydroxyl radicals (OH) | by penicilloylated bovine IgG (BPO-BGG)
    and biparietal diameter (AD-BPD)
  of those, in gold                                                    0
  gold long forms starting with a function word                        4  of 1,199
```

Rejecting them is free on MED1250 today: three false positives removed, no true positive lost. On
institutional prose the same defect is systematic, because the backwards scan aligns the short form's
leading letter with the nearer function word.

```
un-gated -- shipped engine, stock Config()
  "The Office of Management and Budget (OMB) ..."   -> ('OMB',  'of Management and Budget')
  "... Office of Foreign Assets Control (OFAC) ..." -> ('OFAC', 'of Foreign Assets Control')
  "accidental death and dismemberment (AD&D) ..."   -> ('AD&D', 'and dismemberment')
  control: "The Bureau of Labor Statistics (BLS)"   -> ('BLS',  'Bureau of Labor Statistics')  correct
```

**Be precise about what this buys.** It removes a wrong answer; it does not recover the right one.
Checked against the strategy cascade, `OMB` aligns to `of / management / budget` at confidence `1.0`
— the cascade *confirms* the truncation rather than fixing it, which is one more reason the cascade
is not the answer here. Whether the correct span can then be found is unmeasured, and the
boundary-maximising route to it is what D-008 already reverted.

**How it fails.** Four MED1250 gold long forms do begin with a function word, so the rule caps recall
there permanently. It is free only because the extractor finds none of them today; if a future recall
change starts reaching them, the rule becomes a cost and must be re-measured rather than assumed
still free.

### 5. Fix three governed defects and one documentation gap — hours

**`normalize` is not idempotent**, contradicting a stated invariant, in pure ASCII, with a two-row
catalog — and the meaning of the name changes between passes.

```
un-gated -- shipped public API only
  cat = GovernedDictionary.from_mapping({"11": "Eleven", "911": "Emergency"})
  normalize("E_9_1_1", cat)                  -> 'E_9_11'
  normalize("E_9_11",  cat)                  -> 'E_911'      <- moved again
  expand_identifier("E_9_1_1", cat).phrase   -> 'E 9 Eleven'
  expand_identifier("E_911",   cat).phrase   -> 'E Emergency'
docs/GOVERNED_NAMING.md: "normalize(normalize(x)) == normalize(x), for every ASCII x and
every policy" ... "It holds by construction rather than by luck."
```

`tests/test_governed.py::test_normalize_is_idempotent_under_every_policy` parametrises over
identifiers and policies against one fixture catalog, so no catalog shape is ever varied and this
cannot fire. Widen it over catalogs.

**`[` and `]` are unconditionally treated as SQL quoting**, so a character is dropped and a token
invented while the losslessness report says nothing was lost.

```
un-gated
  split_identifier_parts('value[x]')               -> tokens ('value','x')            unaccounted ()
  split_identifier_parts('[db].[schema].[TXN_ID]') -> tokens ('db','schema','TXN','ID') unaccounted ()
```

The second line is why auditor 1's proposed fix is wrong: the brackets do not wrap the whole
identifier there either. A correct fix runs the matched-pair test per dot-segment, which reintroduces
the "is a dot a path separator" question `acronymkit.governed` deliberately refuses to answer. This
is a D-024 decision to re-open with a design, not a patch, and it touches a 91 KB published wire
contract and eight golden fixtures.

**`with_custom` drops subclass state**, and the failure surfaces later as an `AttributeError` from
inside a lookup.

```
un-gated
  class Sub(GovernedDictionary): sets self._extra in __init__
  s = Sub.from_mapping({'TXN':'Transaction'});  hasattr(s, '_extra')             -> True
  c = s.with_custom({'ZZ':'Zed'});  type(c).__name__ == 'Sub',  hasattr(c,'_extra') -> False
```

**The documentation gap.** Add a sentence to `docs/GOVERNED_NAMING.md` saying that on a legacy schema
the round trip's `corrected` bucket will hold nearly everything and `inconsistent` will read zero, and
that this is the standard doing its job rather than the trip being clean. The report is correct; the
surprise is real, and it cost an auditor a headline.

**How it fails.** The idempotence fix needs a decision, not a patch: running `_rejoin_digit_tokens` to
a fixed point makes tokenisation depend on the catalog more aggressively than the tokeniser's "one
literal pass, then one greedy pass" contract allows, while rejecting nesting digit-leading keys at
build time breaks a catalog holding both `11` and `911`, which a municipal standard plausibly does.
The bracket work is a wire-contract change and may legitimately be deferred; what may not be deferred
is leaving the losslessness guarantee reporting a clean result while a character is gone.

### 6. Support `SF = LF` legend syntax, behind a flag, defaulting off — days

The single largest miss class on the newest corpus, and a recall lever operating exactly where
D-012's pseudo-precision diagnosis does not bite: it adds candidates that do not exist, rather than
re-ranking ones that do.

```
un-gated -- SDU@AAAI-22 AE dev; regex over the 30 characters preceding each gold long-form span,
decomposed by separator during the adversarial re-check
  LEGAL       669 gold long forms, 263 missed;  legend matches {'=': 127, ':': 4}
              missed legend {'=': 127, ':': 1}   = 19.6 % of gold, 48.7 % of all misses
  SCIENTIFIC  720 gold long forms, 230 missed;  legend matches {'=': 102, ':': 13}
              missed legend {'=': 102, ':': 4}   = 46.1 % of all misses
  examples: "Abbreviations: AOS = administrative and operational services",
            "GEF = Global Environment Facility"
```

It is not domain-specific — it is near-equal across both splits — so it is a corpus-convention gap,
not evidence about legal text. Gate the long form on the existing character-alignment test.

**How it fails.** `X = Y` is also the surface of every equation and assignment, and the miss dump
contains `Tsat=Tamb [kPa]`, `wC = carbon mass fraction` and `xH2Oexhdry`. A naive rule bleeds
precision on scientific text, where precision is this library's whole thesis. If MED1250 precision
drops at all, revert and log it as experiment eight. The honest prior is that it helps recall on
SDU-22 and does nothing or slight harm on MED1250.

### 7. Make collaborators injectable and finish `acronymkit.data` — days

Covered in full under question 4. Ranked last because it moves no accuracy number, and on the list at
all because two documented extension points do not exist.

### Do not do these

**Do not take the per-candidate-evidence lever.** D-012 identified it as the one untried direction;
D-016 then built per-candidate statistics and reverted them; and the audit has now bounded it.

```
bench/results.json, analysis.med1250.selection_ceiling
  greedy_wrong                                      131
  wrong_gold_not_a_start_boundary                    44
  wrong_gold_explained_by_no_strategy                65
  already_unique_under_per_rule_score                 5
  addressable_by_per_candidate_score                 22    pairs, out of 1,221 gold
  oracle_selector_exact_f1                        85.44    against a baseline of 83.85
```

A *perfect* selector over the whole space is worth about a point and a half, of which the shipped
per-rule score already claims five of the twenty-two pairs. D-012's premise that Ab3P consults
per-candidate term frequency is also wrong: `SingTermFreq.dat` is `2,474,596` unigram rows with zero
multi-word keys, compiled to a `94,718`-word set and used by `is_subword` as a membership test.
Measured with the real file, no threshold makes a single net-positive boundary decision
(`analysis.med1250.unigram_frequency_separation`). Close this line in `docs/DECISIONS.md`, and retire
D-011's `88.49` headroom figure, which over-counts by including spans no matching rule can produce.

**Do not relax digits in the short form.** Measured; loses on every split, including the dev half, so
it would have been rejected without spending test.

```
bench/results.json, relaxation.med1250_all.*
  baseline  83.85     drop_all_digits  82.22     drop_trailing_digits  83.34
```

**Do not delete `register` and `initials` from the disambiguation blend.** They are provably inert on
SDU-21 — `register` varies within a candidate set in `0.00 %` of instances, because every expansion in
`diction.json` is lower-cased — but that is a property of this corpus file, not of the API's contract.
A caller mixing `Multiple Sclerosis` with `mass spectrometry` gets real signal from `register`.
Deleting them optimises for the benchmark's shape, which is the failure `bench/splits.toml` exists to
prevent. Document them accurately and add a knob.

**Do not split the package into two distributions yet.** The drift is real and quantified — governed
is `37.2 %` of source, `42` of `87` public symbols and `7` of `16` CLI commands, while `disambiguate`
has no CLI command at all — but the case rests on knowing which audience is showing up, and nobody
does. Invert the README ordering, which is free and reversible, and revisit when there is usage
evidence.

## 2. Data: what may be benchmarked, what may be shipped

The project's own distinction — a licence that forbids **redistribution** does not forbid **use as a
benchmark** — decides most of this table. Everything below was verified live during the audit;
licence claims read from a badge rather than from the terms are marked and are not trusted.

| Source | Task | Licence, as verified | Benchmark | Vendor |
|---|---|---|---|---|
| SDU@AAAI-22 AE, English legal + scientific | span detection | CC BY-NC-SA 4.0 dataset; MIT covers scorer and baseline only | yes | no |
| SDU@AAAI-21 AI | span detection | CC BY-NC-SA 4.0 — `splits.toml` says MIT and is **wrong** | yes | no |
| Federal Register | none (unannotated) | 17 U.S.C. §105, public domain | yes | yes |
| govinfo bulk (CFR, eCFR, BILLS) | none | §105, public domain | yes | yes |
| SEC EDGAR filings | none | no licence and no copyright statement published; §105 does **not** cover registrant-authored filings | yes | undetermined |
| NameGuess / Columbo | column expansion (synthetic) | Apache-2.0 | only with the section 0 caveat | not useful |
| GLADIS | disambiguation + counts | GitHub badge CC0; Zenodo CC BY 4.0; sources include UMLS | contested | no |
| PMC OA commercial-use subset | raw text | per-article CC BY / CC0, with a CC BY-ND trap | yes | derived only |
| PLOD | span detection | CC BY-SA 4.0 | yes | no |
| MED1250 | pairs | US Government Work, public domain | yes | fetch-only, by size |

Four candidates are not usable today and should be recorded as such rather than left vague:
CourtListener (search open, opinion bodies 401, bulk path 404), USPTO (DNS failure from this host,
which may be local interception rather than an outage — re-probe from elsewhere before writing it
off), arXiv (its *default* licence limits re-use, so only the per-paper CC BY/CC0 subset is a corpus),
and Wikipedia (CC BY-SA, so share-alike travels to derived statistics exactly as `splits.toml`
already reasons for PLOD).

### Three corrections to make in `bench/splits.toml`

**It does not parse.** Line 76 redefines `status` inside `[corpora.plod]`, which line 73 already set.
No tool in the repository reads it; every reference is prose in a docstring or a comment.

```
un-gated
  python -c "import tomllib; tomllib.load(open('bench/splits.toml','rb'))"
  -> TOMLDecodeError: Cannot overwrite a value (at line 76, column 38)
  grep for 'splits.toml' across *.py and *.yml: 11 hits, all prose, no loader
```

The file operating rule 2 rests on is currently a text file nothing validates. Fix the duplicate key
and add a parse check to CI or to the claims gate. This is minutes of work, and it is the difference
between a rule and a habit.

**`[corpora.sdu21_ai].licence = "MIT"` is wrong**, in the same way the `sdu21_ad` entry already was.

```
un-gated -- verified live, raw.githubusercontent.com/.../AAAI-21-SDU-shared-task-1-AI/master/README.md
  "The dataset provided for this shared task is licensed under CC BY-NC-SA 4.0 international
   license, and the evaluation script and the baseline are licensed under MIT license."
```

Apply the CORRECTION block the `sdu21_ad` entry carries. The HuggingFace mirror
`amirveyseh/acronym_identification` is tagged `license: mit`, so the error propagates to anyone
trusting the badge.

**Register SDU@AAAI-22 AE, and label its domain honestly.** It is fetchable today and it is the
project's first non-biomedical annotated corpus.

```
un-gated -- verified live 2026-08-23, raw.githubusercontent.com/amirveyseh/AAAI-22-SDU-shared-task-1-AE
  english/legal/train.json       3,564 samples   3,554 labelled   1,733,260 B
  english/legal/dev.json           445 samples     444 labelled     291,388 B
  english/legal/test.json          446 samples       0 labelled     201,639 B   (unlabelled)
  english/scientific/dev.json      497 samples     497 labelled     189,240 B
```

The library scores far below its biomedical figures on it, measured twice independently with the
task's own scorer:

```
un-gated -- NOT in bench/results.json; scratch runner over the task's own scorer.py
  LEGAL       Shorts P 93.66 R 37.76 F1 53.82 | Longs P 82.69 R 60.69 F1 70.00 | macro F1 63.18
  SCIENTIFIC  Shorts P 95.90 R 57.84 F1 72.15 | Longs P 83.76 R 68.06 F1 75.10 | macro F1 74.02
```

**Two caveats must ship with any table quoting those.** First, "legal" is the corpus's word, not a
description. Sampling the dev split returns UNEP environmental cooperation, a UNECE innovation-policy
note, Human Development Index analysis and UN procurement committee reporting. It is institutional
and development-policy prose. Calling it legal-domain evidence would be the PLOD mistake repeated
deliberately, and this project already paid for that once. Second, a definition-only extractor cannot
exceed a short-form recall ceiling here, because the corpus annotates every acronym occurrence while
the library reports only defined pairs — the ceiling is about `55 %` on legal and `74 %` on
scientific. Print the ceiling in the same table or the recall figure misleads. With the ceiling
artifact and the legend class removed, the residual domain gap is roughly `4.6` points of long-form
recall, not the raw `10.84`.

### PMC: mirror or do not, but decide on the merits

The pinned path is dead and the deprecated mirror is up as of today.

```
un-gated -- verified live, 2026-08-23
  HEAD ftp.ncbi.nlm.nih.gov/pub/pmc/oa_comm/                          -> 404
  HEAD ftp.ncbi.nlm.nih.gov/pub/pmc/deprecated/oa_bulk/oa_comm/txt/   -> 200
```

D-020 item 3 already recorded the 24 August 2026 deadline, so the deadline is not news; that the old
pin is *already* 404 and the content survives only under `deprecated/` is. **Do not mirror it for the
frequency prior.** Two measurements settle that:

```
un-gated -- from a real 3,028-article PMC sample
  senses of SDU-21 AD's 732-acronym inventory matched by a PMC-derived prior     4.72 %
  Heaps fit over a 30x range, beta 1.0028-1.036, extrapolated to 5.27M articles
                                                                            32-42 M rows
                                                                          455-600 MB gzipped
```

Against which the actual constraint is:

```
un-gated -- python -m build --wheel, 2026-08-23
  acronymkit-0.3.0-py3-none-any.whl        565,730 B
  ci.yml BUDGET_BYTES                      786,432 B
  headroom                                 220,702 B
```

D-020 says "Headroom today is 113,269 bytes". That is stale by roughly a factor of two — it was
derived under the previous budget — and two auditors re-quoted it as current. The conclusion is
unchanged, because 455 MB clears either figure by four orders of magnitude, but `ci.yml`'s own comment
says to re-derive the rationale rather than re-quote it. Fix the number in D-020.

The decisive objection is aim, not size: a PMC prior is a biomedical prior, and the measured
disambiguation deficit is on computer-science text. One narrow reason to mirror survives — `5.27 M`
CC BY / CC0 full texts is a reusable held-out extraction corpus in its own right, independent of any
prior. Take that decision deliberately and log it; do not take it by default because a deadline is
loud. If the answer is no, record the skip.

One trap to carry forward if anyone does fetch it: PMC's own documentation groups `cc_by-nd_license`
under the filter for "articles that permit commercial reuse". Commercial reuse and derivative works
are not the same permission. ND and SA articles must both be excluded per-article, which the `License`
column of every shipped `filelist.csv` makes a one-line filter.

### Building our own gold standard

There is no held-out short-form/long-form pair corpus and `bench/splits.toml` says so. The audit
produced a costing, not a corpus.

- **Substrate:** the Federal Register, not EDGAR. §105 public domain, a documented JSON API,
  plain-text bodies, and — decisively — its rules routinely carry their own abbreviation legends, so
  the arbiter can be the agency rather than us. Yield measured at roughly `120` distinct pairs per MB.
- **Recipe:** pool candidates from three independent extractors (acronymkit, the all-caps one-liner,
  and one external tool already benchmarked); adjudicate the union *plus* a random sample of
  unproposed parentheticals, so the false-negative rate is estimable rather than assumed; publish the
  pooling recipe and the agreement statistic; freeze the split before anyone touches a knob.
- **Cost:** an adjudication pilot over 120 EDGAR pairs ran at roughly twelve pairs a minute, making a
  2,000-pair set a few days of one person's attention rather than a research programme.

**How it fails.** Every candidate still comes from a parenthesis-or-uppercase heuristic, so the corpus
would systematically under-represent exactly the forms all three systems miss — the `SF = LF` legends
and the quoted defined terms this audit found. The random-unproposed-sample step is what catches that
and must not be dropped for budget. Single-annotator work is not a gold standard; if a second
adjudicator cannot be found, label it "single-annotator reference set" and never quote a headline off
it. And the Federal Register skews environmental, aviation and fisheries — it is one more domain, not
"general text".

## 3. What we do not know, ranked by what the answer would change

### 1. Does a governed catalog add anything on a real schema?

The audit's most consequential unknown, and existential for `acronymkit.governed`. Under a
portal-disjoint split of real Socrata schemas, a voted catalog beat an **empty** catalog by
essentially nothing — because real schemas are already spelled out, and Title Casing does the work.

```
un-gated -- adversarial pass, 164,652 field/display pairs, 9 portals, seed 20260809
  held-out portals, 6,548-row voted catalog       48.60 %  exact
  held-out portals, EMPTY catalog                 49.55 %  exact
```

The adversary refused to assert that as a result, and was right to: Socrata display labels are a noisy
gold — `':@computed_region_92fq_4b7q'` captions as `'City Council Districts 2'` — and `78.9 %` of
abbreviation-carrying pairs have a token count that does not match the label's word count. The
structural fact underneath is robust, though: `87.3 %` of real field/label pairs are already
unabbreviated.

**What changes on the answer.** If a catalog genuinely adds little on real input, the subsystem's
value is provenance and compliance — `entry_id`, `source`, `beat`, the unknown-token work list — and
not expansion accuracy, and the docs and README should say so plainly. If it adds a lot once the gold
is clean, the catalog-transfer curve is the headline this subsystem has been missing. **How to answer
it:** obtain one real proprietary data-standards glossary, under NDA if necessary, and measure against
the schema it governs. Nothing public substitutes. Every catalog measured in this audit was inferred
by the auditor from the very labels used as gold, which is circular by construction.

### 2. Does anyone pass a dictionary to `disambiguate`?

The whole measured disambiguation failure lives in one code path.

```
bench/results.json, disambiguation.sdu21.diagnosis.default_path
  with no dictionary: no candidate at all   97.45 %       two or more candidates   1 of 6,189
```

The documented default performs no selection at all; it is an inline-definition lookup. **What changes
on the answer:** if nobody passes a dictionary, recommendation 1 is a reputational fix and should be
scoped to abstention alone; if the README's framing has drawn people to it, the weighted-dictionary
work is urgent. Download counts and issue-tracker traffic would settle it in an afternoon, and nobody
has looked.

### 3. Does the legend rule hold precision on MED1250?

Decides recommendation 6 outright, and it is one afternoon against a runner that already exists. If
precision moves at all, revert and log experiment eight.

### 4. Is there a held-out extraction number anywhere?

`bench/splits.toml` records none, so every MED1250 figure on this page — including the one that would
move the library to second place on its flagship table — is a tuning-split figure, and the dev/test
halves are two halves of a contaminated set. SDU-21 AD `test.json` is fetchable from the same pin and
was deliberately left unspent by an earlier round. It is the right thing to spend on confirming an
abstention policy, and it can only be spent once.

### 5. Is the two-word fix safe outside biomedical prose?

Partly answered, and pointing both ways: precision **up** on SDU-22 legal, pooled precision **down** on
PLOD, neutral on PLOD test. Enough to know it is a trade; not enough to know its sign in general
prose. One more corpus decides it.

### 6. The non-ASCII path has never met real data

Zero of `107,012` real identifiers were non-ASCII, so `_scan` — the reference reading of the
tokenisation rules, and the half the docstring calls authoritative — was never exercised by a real
name. Everything measured went through the ASCII regex. There is no field evidence about the other
branch at all.

### 7. Does the abstention threshold hold out of sample?

Every point on the coverage/accuracy curve comes from a declared tuning split. The curve is monotone
and well populated, so its shape is trustworthy; the specific cut-point is not.

**Deliberately not listed**, because the answer changes nothing: the exact PMC download time, the
precise memory profile at a million columns, whether USPTO is reachable from a different network, and
the true full-scale count distribution of a PMC prior already ruled out on aim rather than on size.

## 4. How to let people customise it

The pattern is consistent across both halves of the library. Everything expressible as a **value** — a
weight, a path, a word set, a catalog row, an overlay — is customisable, documented, and works.
Everything that would be expressed as **behaviour** — a tagger, a scoring term, a splitter, a resolver
— has no seam, and the only route is assigning to an underscore slot on a `__slots__` class. There is
no registry, no `register_*` function and no plugin loader in `src/`.

Two of those gaps are worse than "missing feature", because the documentation says they exist.

### A. Injectable collaborators — hours, zero gate risk

```python
class AcronymEngine:
    def __init__(
        self,
        config: Optional[Config] = None,
        *,
        backend: Optional[NlpBackend] = None,
        tokenizer: Optional[Tokenizer] = None,
        extractor: Optional[AbbreviationExtractor] = None,
        scorer: Optional[Scorer] = None,
    ) -> None: ...
```

Today the signature takes `config` alone, while README.md and `docs/ARCHITECTURE.md` both advertise
"Plug in your own tagger — implement the `NlpBackend` protocol". The protocol is real and `isinstance`
passes; there is no socket.

```
un-gated
  inspect.signature(AcronymEngine.__init__)     ->  (self, config: Optional[Config] = None) -> None
  AcronymEngine(Config(), backend=MyTagger())   ->  TypeError: unexpected keyword argument 'backend'
  NlpBackend members                            ->  ['annotate', 'is_available']
```

When `backend` is supplied, recompute `_engine_tier` from it — otherwise `engine_tier` keeps reporting
the tier of the backend `resolve_backend` returned, which is a metadata lie. Promote `NlpBackend` to a
documented public export alongside `SupportsLexicon` and `SupportsPronounceability`, which `Scorer`
already duck-types. No entry points, no discovery, no import-time cost, nothing added to `sys.modules`.

**Cost.** `AcronymEngine` documents itself as safe to share across threads *because* it builds
everything it holds. An injected mutable collaborator voids that, so the guarantee becomes conditional
on what was passed in and the docstring has to say so.

**Precondition, not a follow-up.** A `scorer=` argument today is a footgun: `ForwardGenerator._beam_bound`
re-derives the objective from the `ScoringWeights` fields and never calls the scorer, so a custom term
re-ranks the retained frontier and cannot enlarge it. Measured on a 15-word phrase, `beam=4` returned
3 candidates against 500 at an effectively unbounded beam, and a `+5000` custom term rescued none of
the 499. `Config.fast()` ships `beam=32`. Either document the limit precisely on `Scorer` and on the
new argument, or give the scorer a `bound(state) -> float` that `_beam_bound` calls, defaulting to
today's closed form. The second option needs a property test asserting admissibility and a re-run of
the generation benchmark to prove the default path did not move — a `--save`, not a claim.

### B. `GovernedDictionary`: a real resolver hook — days

```python
class GovernedDictionary:
    def __init__(
        self,
        entries: Iterable[GovernedEntry] = (),
        *,
        custom: Optional[Mapping[str, Union[str, GovernedEntry]]] = None,
        resolver: Optional[Callable[[str], Optional[str]]] = None,   # new
        ...
    ) -> None: ...
```

Consulted only after the catalog, the overlay and the allow-lists have all declined. Its answers carry
a new `ExpansionSource.RESOLVED` — never `CUSTOM` — and stay **out** of `is_fully_known`, so a resolved
token reads as "something answered for this, and it was not the catalog". Fix `with_custom` to copy
`self.__dict__` onto the clone in the same change; today the subclass workaround silently loses its
state, and the failure surfaces as an `AttributeError` from inside a lookup.

**Cost, and it is the highest in this section.** Adding an `ExpansionSource` member is a wire-contract
change: it touches the 91 KB `docs/notes/governed-json-contract.md`, which declares the enum "in strict
precedence", eight golden JSONL fixtures, and any future JVM port D-028 keeps the door open for. The
deeper cost is cultural — a resolver is mutable, possibly network-touching and non-deterministic,
bolted onto a subsystem whose three stated properties are context-free, deterministic and auditable.
It must be documented as breaking determinism and reproducibility, and forbidden under `Config.offline`,
or it becomes a second hole beside pydantic's in the air-gap promise.

The supported route today is two passes — `audit_identifiers` → `unknown_tokens` → resolve → rebuild
with `custom=` — which works, costs a full extra pass, and cannot work on the stream shape
`governed-batch` was built around.

### C. Finish `acronymkit.data` — days

The entry-point group is declared, discovered, printed by `doctor`, and consumed by nothing.

```
un-gated
  grep -rn 'DATA_PACK_GROUP|acronymkit.data' src/  ->  3 lines, all in diagnostics.py
  union of acronymkit / governed / diagnostics __all__, filtered for 'pack'
                                                   ->  ['DATA_PACK_GROUP']
  capabilities()['data_packs']                     ->  []
```

An auditor built a working pack as a separate distribution: `capabilities()` discovered it with no
change to the base package, `doctor` printed it, and discovery imported nothing. The hard, correct
half is already done. What is missing is a loader and a descriptor contract.

```python
# acronymkit/governed/packs.py
def installed_packs() -> tuple[PackInfo, ...]: ...          # metadata only, imports nothing
def describe_pack(name: str) -> PackInfo: ...               # imports the one pack named
def load_pack(
    name: str, *, policy=None, custom=None, allow_non_redistributable: bool = False
) -> GovernedNamer: ...
```

The entry point resolves to a frozen object carrying `schema`, `name`, `version`, `kind`, `languages`,
`data_license`, `redistributable` and `path()`. Refuse an unknown `schema`; refuse a `kind` this
release has no consumer for; refuse `redistributable=False` unless the caller opts in — that last one
is licence discipline made executable instead of documented. Steal Sphinx's shape (explicit opt-in by
name, self-describing metadata, nothing loaded until asked), not spaCy's or pydantic's, both of which
load eagerly and implicitly.

**Never scan entry points at import.** The measurement is unambiguous:

```
un-gated -- subprocess timing, min of 7
  bare `import acronymkit`, 8-distribution venv                       7.71 ms
  entry_points(group='acronymkit.data'), same venv                    3.36 ms
  the same scan, this machine's main interpreter (584 distributions) 47.53 ms
```

A scan on the import path would be the largest single regression this package has ever taken to its
cheapest operation. Note also that the Tier 0 purity gate asserts against a fixed deny-list, so it
would not catch a badly-behaved pack — and would fire on an unrelated commit if packs were ever loaded
eagerly. That is the same gate hole the project already documented for pydantic's own entry-point
group and refused to accept.

**Cost.** `load_bundle` currently raises a bare `TypeError`, outside the library's exception hierarchy,
on a zip-imported pack's `Traversable`, so packs would be quietly filesystem-only unless that is fixed
in the same change. `redistributable` is a self-declaration: a signal an enterprise CI can assert on,
not enforcement, and describing it as enforcement would be the kind of overclaim this project reverts.
The load-bearing assumption is that anyone would publish a pack; the honest test is whether this
project would ship one within a release or two. If not, do not build the loader.

### D. What should stay closed

**The strategy cascade.** `acronymkit._strategies` and `acronymkit._pseudo_precision` are the largest
piece of finished extensibility machinery in the repository — 30 parameterised rules and a fitted,
shipped precision table — and publishing them as an accuracy lever would sell a knob measured not to
turn. D-010 built the cascade and reverted it; D-008 built the boundary-maximising selector and
reverted it; and the cascade confirms the `OMB` truncation at confidence `1.0`. If it is ever made
public, the docstring must say it is a *rule set*, not a *ranker*, and it should not be started before
a non-biomedical gold standard exists. Making the rule names public also fixes them as API, which
D-019 already recorded biting once.

**Adding a language.** Closed at four independent points — the `Language` enum cannot be extended,
`Config(language=...)` validates against it, `from_tag` rejects unknown tags, and the resource files
are generated. `CONTRIBUTING.md` states the requirement plainly, and it is a fork-or-PR rather than a
customisation. Note that the three declared non-English languages are themselves only half-supported:
`available_languages` returns English alone for both lexicon and n-gram, so `fr`, `es` and `de` each
raise degradation warnings today. A "language pack" would be impossible even with a pack loader.

## If you only do one thing

**Make `LexicalDisambiguator` abstain, and give `ExpansionDictionary` an optional per-expansion weight
that blends with the context score. Ship no counts.**

```
bench/results.json
  disambiguation.sdu21.acronymkit.accuracy                                       41.65
  disambiguation.sdu21.most_frequent.accuracy                                    72.84
  disambiguation.sdu21.diagnosis.frequency_prior.accuracy_interpolation_out_of_fold
                                                                                 76.67
  disambiguation.sdu21.diagnosis.abstention.margin_gate_0.10_accuracy_when_answered
                                                                                 70.35  at 22.67 % coverage
  disambiguation.sdu21.diagnosis.frequency_prior.instances_context_right_prior_wrong_pct
                                                                                 11.33
```

It is the largest measured gain in the audit and the only large one that needs no corpus, no licence
and no data in the wheel. The abstention half is free: the engine already computes the margin that
separates its right answers from its wrong ones and throws it away. Today a caller cannot distinguish
an answer from a guess, because both arrive with a plausible-looking score attached. That is precisely
the failure `acronymkit.governed` was designed to prevent, in the module that commits it worst, and
fixing it is the project applying its own thesis to itself. The same measurement also settles whether
to withdraw the capability: context is uniquely right on `11.33 %` of instances the prior gets wrong,
so prior and context are complementary rather than substitutes, and a library shipping only a prior
would leave that on the table.

**What would tell you it was the wrong call.** Two things. First, if nobody passes a dictionary to
`disambiguate`: the default path returns no candidate on `97.45 %` of instances and performs no
selection at all, so the entire measured failure is confined to a code path that may have no users,
and this would be a reputational fix dressed as an engineering one. Download and issue-tracker
evidence would show that in an afternoon, and it should be gathered before the weighted-dictionary
half is built. Second, if the interpolation weight does not transfer: `lambda = 0.60` was fitted
against one prior, drawn from the same corpus and domain as the evaluation, and a caller's sparser,
out-of-domain, differently-smoothed prior could put the optimum somewhere a hard-coded default makes
worse than their counts unblended. Expose lambda and default prior-dominant; if the first external
caller with real counts reports the blend underperforming the prior alone, the weighted-dictionary
half was wrong and only the abstention half should have shipped.
